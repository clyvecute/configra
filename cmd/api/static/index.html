Features

Everything you need.
Nothing you don't.

Built on strict Twelve-Factor App principles for 100% parity between local and cloud.

🔒

Immutable History

Every change creates a new, append-only version. The past can never be rewritten — you always know who changed what, and when.

✓

Schema Enforcement

Strict type validation (String, Int, Float, Bool, Enum, JSON) at both the CLI and API layer. Bad data is rejected before it ever reaches production.

⚡

Atomic Rollbacks

Instantly restore any previous known-good state. Rollbacks are non-destructive — they create a new version with the old content, preserving full lineage.

🔑

API Key Auth

Per-project API keys with scoped access. Your API key determines your project scope — callers cannot spoof a different project's configs.

☁

Cloud Native

Stateless Go binary deployable to Cloud Run, Render, Fly.io, or Railway. All config comes from environment variables.

🔧

CLI First

Validate configs locally before pushing. The same validation logic runs in the CLI and the server — no surprises at push time.

How it works

From local file to versioned,
validated production config.

1

Define your schema

Write a schema.json declaring every key, its type, whether it's required, and any constraints. This becomes your configuration contract.

2

Validate locally

Run configra validate before any push. Zero network calls — pure local logic. Catch type errors and missing fields before they reach your API.

3

Push & version

Run configra push. The server re-validates, records a new immutable version, and returns the new version number. Every push is atomic.

4

Rollback when needed

Run configra rollback -version N. A new version is appended with the contents of version N. History is always preserved. Zero downtime.

API Reference

Simple, JSON-native REST API.

All endpoints return application/json. Auth via X-API-Key header.

MethodEndpointDescription
GET/healthLiveness check. Returns 200 when the service is up.
POST/v1/validateDry-run schema validation — no auth, no DB write.
POST/v1/configsCreate or update a config key. Requires API key. Returns the new version.
GET/v1/configsFetch the latest version of a config key. Requires API key.
POST/v1/rollbackRollback to a target version (non-destructive). Requires API key.
